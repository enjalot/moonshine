Embeddings: text as a list of numbers

An embedding model turns text into numbers that encode meaning. Similar texts get similar numbers.

By Ian Johnson

What is an embedding?

Take a sentence and feed it to an embedding model. This is a language model that, instead of generating more text, returns a list of numbers describing what it read: 384 of them, for the model used in this series.

This list is called an embedding. Each number is a dimension. Together they place the sentence at a specific point in a high-dimensional space. Where it lands depends on what the model learned during training.

Squinting at that bar chart, there is no obvious pattern a person could read. But the model that produced it was trained on enormous amounts of text, and the positions of these numbers relative to each other encode something about what the sentence means, which we can see once we compare one embedding with another.

Measuring similarity between two embeddings

When two pieces of text are about the same thing, their embeddings land near each other in that high-dimensional space. We can measure how close they are with cosine similarity: a score of 1 when two embeddings point the same way, falling toward 0 as they become unrelated.

similarity(A, B) = A · B / (‖A‖ ‖B‖)

In practice the scores from this model don't use the whole range. Across a collection of 1,000 dad jokes, a typical pair scores about 0.5, and almost no pair scores under 0.3, so read a score against that baseline. Figure 2 starts with a joke and the closest joke to it in the collection. Change Joke B to one further away and watch the difference grow.

Searching by meaning

We have a collection of dad jokes, each one already embedded. To search them, we embed a query and find the jokes whose embeddings are closest. This is nearest neighbor search: finding the points in the space that are most similar to your point.

So wording counts as well as subject, and the model weighs both. It has read enough text to develop a sense of what words mean, what topics relate to each other, what structures look similar. When we embed our data through this model, we get to look at our data through the lens of everything the model has learned.

Choosing an embedding model

There are many embedding models, each trained on different data with different objectives. One model might be trained for search relevance, another for semantic similarity, another for code understanding. The same text, embedded through different models, produces different numbers and different similarity rankings.

The choice of model shapes what you see. A model trained heavily on scientific papers might place two chemistry jokes closer together than a general-purpose model would. A model trained for retrieval might care more about topical overlap than tone or structure.

For Parts 1 to 3 of this series, we use bge-small-en-v1.5, a model that produces 384-dimensional embeddings. It is a general-purpose model: competent across a wide range of text, not specialized for any one domain. In the next article, we will take these embeddings and project them into two dimensions so we can see the whole collection at once.
