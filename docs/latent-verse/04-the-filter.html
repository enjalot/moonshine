Latent Verse / Part 4: the filter

Decomposing embeddings with a sparse autoencoder

A sparse autoencoder breaks an embedding into a few labeled features. It works on any text the model can embed, including text from other datasets.

By Ian Johnson

Why clusters don't transfer to other datasets

In the previous articles, we used tools that are local to a dataset. Each time we ran UMAP, we got a new projection. Each time we clustered, we got new groups. These are useful for exploring a specific collection, but they don't generalize. The clusters you find in dad jokes tell you nothing about a collection of news articles.

A different kind of tool decomposes any text the model can embed into interpretable features, using one vocabulary of concepts for every dataset.

That tool is a sparse autoencoder (SAE). It learns to break an embedding into a small number of active features chosen from a much larger set of possible features. We can think of it as a filter that separates an embedding into its ingredients.

What is an SAE feature?

An embedding is a dense vector: all 384 dimensions have nonzero values, and none of them means anything on its own. An SAE turns it into a sparse vector. The one in this article has 49,152 features, and exactly 64 of them are active for any text. Each feature has a short label.

The SAE was trained on all-MiniLM-L6-v2 embeddings of web text from FineWeb-edu, RedPajama and the Pile. A language model wrote each label after reading the web passages that activate that feature most. No jokes were used in training or labeling. An SAE only works with the embedding model it was trained on, so from here on the jokes are embedded with MiniLM instead of the bge-small model used in Parts 1 to 3. Both models produce 384 numbers per text.

A feature is a direction in the embedding space that the SAE learned, together with a number saying how strongly a given text activates it. Here are the eight strongest features of one joke, and you can pick another:

For the atoms joke, red features name its subject (atoms, nuclear technology) and one of them, "certificate trust validation", comes from the single word trust.

The specific features name what the joke is about: atoms and nuclear technology, noodles, bicycles, the moon. Some respond to a single word in its most common web sense. The atoms joke activates "certificate trust validation" because it contains trust, and the scarecrow joke activates "escrow arrangements", most likely because scarecrow and escrow share their last letters.

None of the features describe the pun. "Two tired" and "impasta" leave no trace in the labels. Of these twelve, only the egg joke activates the humor features, and only because it contains the word jokes. An SAE describes what the embedding encodes, and this embedding encodes the words and topics a joke is built from, not the wordplay.

The broad features are shared most often. "Literary scenes and characters" is active for 37,469 of the 52,573 jokes, most strongly for jokes told as a story, and "absence and void concepts" for 15,314: any joke built on no or without, such as the bear with no teeth or the restaurant with no atmosphere. Broad features describe the form of a text more than its subject. The next article shows that this difference is visible on a map.

Using the same features on any dataset

Clusters are computed from a dataset and apply only to that dataset. SAE features are trained to match the embedding model, so they apply to any text the model can embed. The same 49,152 features describe these jokes, a news archive or a set of research abstracts.

That makes the SAE a global tool: one vocabulary for describing what the model sees, whatever data you are looking at. The labels are a starting point, written from web text. As the trust and escrow features show, a label can read oddly on a new kind of text, and the way to check one is to read the texts that activate it.
