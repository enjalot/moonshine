Moonshine

Turn complex technical ideas and AI-generated output into interactive, Distill-style articles you can edit directly on the page.

AI tools help us write code, design systems, and generate documentation faster than ever. They have also created a new problem: the volume of technical output now exceeds our ability to understand it.

We accumulate cognitive debt as AI-generated modules, auto-documented APIs, and synthesized design docs pile up faster than teammates can parse, review, and reason about them.

Inspired by Distill.pub, moonshine helps apply distillation to that flood of technical output. Distillation is the creative work of finding the decomposition, visualization, and sequence of ideas that turn complexity into understanding.

Seeing the Parts

Consider a signal, a complex waveform that is hard to interpret as a whole. Fourier analysis decomposes it into simple sine waves, each with a frequency and amplitude. Toggle individual components on and off to see how they combine.

Why Interactive?

You could read a paragraph explaining that low frequencies carry the signal's overall shape while high frequencies add detail. Or you could turn off the high frequencies yourself and watch the waveform smooth out. The second builds intuition that the first cannot.

Interactive media lets readers explore parameter spaces, test hypotheses, and discover relationships at their own pace. The reader becomes a participant rather than a passive receiver.

That said, interaction needs to earn its place. A slider that does not build intuition is worse than a well-written sentence. Moonshine tries to follow one principle: every interaction should serve understanding.

How It Works

Moonshine is a plugin and set of skills for AI coding agents (Antigravity, Claude Code, and Codex). When invoked, it starts with questions before writing any code, then keeps you in the loop as you edit and refine the result.

1

Story Discovery

What concept are you explaining? Who is the audience? What is the key insight, and what progression gets the reader there?

2

Interaction and Diagram Design

Choose the right medium for each step: plain prose, explorable knobs, declarative dragging (where pulling an output drives the inputs), scrollytelling tours, or icon-tile system diagrams via the diagram skill.

3

Scaffold on still or shine

Use still (the default) for a Vite + React + Velite project with pristine markdown prose and in-page editing, or shine for a single self-contained HTML + D3 file with no build step.

4

Co-Author Directly on the Page

In still, edit prose in place, tune figure knobs, drag blocks to reorder, arrange diagrams by hand (on desktop or tablet), route targeted comments back to the agent, and review word-diff suggestions from critique or editing passes.

Get Started

Antigravity

# Install the native plugin (6 skills + Stop hook)
agy plugin install https://github.com/enjalot/moonshine/tree/main/plugins/moonshine

# Start a new explanation, diagram, or critique
/still how gradient descent finds minima
/diagram architecture of our request pipeline
/critique

Claude Code / Codex

# Add the marketplace and install
/plugin marketplace add enjalot/moonshine
/plugin install moonshine@moonshine-marketplace

# Then start a new explanation
/moonshine:still how gradient descent finds minima   # structured project (Codex: $still)
/moonshine:shine how gradient descent finds minima   # single HTML file (Codex: $shine)
/moonshine:diagram                                   # system/process diagram (Codex: $diagram)
/moonshine:critique                                  # adversarial review (Codex: $critique)

Moonshine asks what you are explaining and who the audience is before writing any code. still scaffolds a Vite + React project where prose stays in markdown and the rendered page is the editing surface: edit blocks in place, tune figure knobs, drag to reorder, arrange icon-tile diagrams, send comments to the agent, and review word-diff suggestions. shine produces a single self-contained HTML file with D3 and no build step. Manual install and development setup are covered in the repo README.

Inspiration

Distill.pub articulated why distillation matters in their essay Research Debt, and published some of the best examples of what interactive explanations can be. Mike Bostock created D3.js and wrote a series of interactive articles that showed how visualization and narrative can work together. Bret Victor imagined explorable explanations. Nicky Case, Setosa, and The Pudding proved the format works across a range of subjects. The Visual Explainer skill showed the potential for agents making visual artifacts. Moonshine tries to make it practical to build interactive explanations with AI assistance.
